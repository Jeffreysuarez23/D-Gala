🔐 TABLA: ADMIN

Gestión de administradores del sistema y control de accesos

Descripción General de Tabla

Propósito: Gestionar credenciales, autenticación y datos de administradores del sistema. Proporciona un nivel de seguridad elevado para el acceso al panel administrativo.
Campos Clave: id, usuario, password (hash), nombre, email, token_password, password_request, activo, fecha_alta
Relaciones: Tabla independiente (sin FK)
ID RF Requerimiento Descripción Profesional Reglas de Negocio (3) Estado Prioridad
RF-001 Autenticación Admin El sistema debe permitir que administradores se autentiquen con usuario y contraseña encriptada utilizando algoritmo bcrypt de 10 rondas. La sesión se mantiene en el servidor con validación de token.
1️⃣ Contraseña Segura
La contraseña debe tener mínimo 8 caracteres, con mayúscula, minúscula y número. Se guarda con hash bcrypt irreversible.
2️⃣ Un Admin Activo
Solo un administrador puede estar activo al mismo tiempo. Campo 'activo' = 1 garantiza acceso exclusivo.
3️⃣ Intento de Acceso
Máximo 3 intentos fallidos para acceder. Después se bloquea por 15 minutos. Log de intentos se registra.
✅ IMPLEMENTADO 🔴 ALTA
RF-002 Recuperar Contraseña El sistema debe generar un token único temporal para recuperación de contraseña válido por 24 horas. Se envía un link seguro al email del administrador registrado con instrucciones para reset.
1️⃣ Token Temporal
Token generado con SHA256 único. Válido solamente 24 horas. Se anula después de ser usado o expirado.
2️⃣ Email Verification
Email debe existir en base de datos. Se enva solo a email registrado. Validate SMTP correctamente.
3️⃣ Nueva Contraseña
Nueva contraseña debe cumplir políticas de seguridad. No puede ser igual a anterior. Log de cambio se registra.
✅ IMPLEMENTADO 🔴 ALTA
RF-003 Gestión de Sesión El sistema debe validar que el administrador tenga sesión activa antes de permitir acceso al panel. Tiemout automático después de 30 minutos de inactividad. Logout limpia todas las variables de sesión.
1️⃣ Timeout Automático
Sesión expira después de 30 minutos sin actividad. Se redirige a login automáticamente sin perder datos.
2️⃣ Validación en Cada Request
Cada página de admin valida sesión activa. Si no existe, redirige a login.php obligatoriamente.
3️⃣ Logout Completo
Al hacer logout se destruyen todas las variables SESSION y cookies. Imposible acceder después sin login.
✅ IMPLEMENTADO 🔴 ALTA

1️⃣ Solo Admin Master
Solo admin_id = 1 (master) puede editar admins. Otros admins solo pueden editar su propio perfil/contraseña.

nombre, email, estado (activo/inactivo). Usuario y contraseña NO son editables por este requerimiento. Inmutables.

RF-004c Eliminar Administrador Admin master puede eliminar (desactivar) administrador. Si es último admin activo, sistema previene eliminación. Soft delete: establece estado = inactivo. Admin sigue existiendo en historial. Puede reactivarse.
1️⃣ Mínimo Un Admin Activo
Sistema debe tener siempre mínimo 1 admin activo. Si intenta desactivar último admin, sistema rechaza con mensaje claro.
2️⃣ Soft Delete
Eliminación = cambiar estado a inactivo. Admin no puede loguearse pero datos se mantienen. Reactivación es posible.
3️⃣ Auditoría Eliminación
Se registra: quién hizo eliminación, cuál admin fue eliminado, cuándo, motivo (si proporciona). Log completo.
❌ NO IMPLEMENTADO 🔴 ALTA
RF-005 Log de Accesos Admin Sistema registra cada login/logout de admin: IP, navegador, fecha/hora, resultado (exitoso/fallido). Admin master puede ver historial de accesos de todos los admins. Útil para auditoría de seguridad.
1️⃣ Captura de Datos
Cada login registra: admin_id, IP ($_SERVER['REMOTE_ADDR']), User-Agent, fecha, hora, resultado (OK/FALLÓ). Tabla logs_admin.
2️⃣ Retención de Logs
Logs se mantienen 90 días. Después se archivan o eliminan. Permite auditoría pero optimiza BD. Limpieza automática cron.
3️⃣ Alertas Seguridad
Si > 5 intentos fallidos en 1 hora desde misma IP, sistema alerta admin master. Previene ataques brute force.
❌ NO IMPLEMENTADO 🟠 MEDIA
RF-006 Búsqueda de Acciones Admin Admin master puede buscar y filtrar acciones de admins: por nombre, email, rango fecha, tipo acción (CREATE/UPDATE/DELETE). Genera reportes de actividad. Útil para monitoreo de cambios en sistema.
1️⃣ Filtros Avanzados
Buscar por: admin (nombre/email), fecha inicio, fecha fin, tipo acción, tabla afectada. Combinación de múltiples filtros.
2️⃣ Exportar Reportes
Resultados se pueden exportar a CSV o PDF. Incluye: admin, acción, tabla, cambios, fecha, hash verificación.
3️⃣ Auditoría Completa
Sistema guarda versión anterior y nueva de datos modificados. Permite ver exactamente qué cambió y por quién.
❌ NO IMPLEMENTADO 🟠 MEDIA

👥 TABLA: CLIENTES

Registro y gestión de clientes del e-commerce

Descripción General de Tabla

Propósito: Almacenar información personal de clientes (nombre, apellido, contacto, documento de identidad). Centro neurálgico para identificación y seguimiento de compradores.
Campos Clave: id, nombre, apellido, email, telefono, documento, estatus, fecha_alta, fecha_modifica, fecha_baja
Relaciones: FK hacia usuarios (1:1), FK hacia compra (1:N), FK hacia direcciones (1:N)
ID RF Requerimiento Descripción Profesional Reglas de Negocio (3) Estado Prioridad
RF-010 Registro de Cliente El sistema permite que nuevos usuarios se registren como clientes proporcionando nombre, apellido, email y teléfono. Validación de email único. Se envía email de confirmación con token de activación.
1️⃣ Email Único
No puede haber dos clientes con el mismo email. Sistema valida unicidad ANTES de guardar registro.
2️⃣ Datos Completos
Nombre y apellido son obligatorios. Email y teléfono obligatorios. Documento de identidad es opcional.
3️⃣ Estado Inicial
Cliente nuevo comienza con estatus = 0 (inactivo) hasta confirmar email. Email de activación válido 48h.
✅ IMPLEMENTADO 🔴 ALTA
RF-011 Perfil de Cliente Cliente registrado puede ver y editar su perfil: nombre, apellido, email, teléfono, documento. Cambios se guardan con audit trail (fecha_modifica). Solo cliente propietario puede editar su perfil.
1️⃣ Autorización
Solo el cliente propietario (usuario logueado) puede editar su perfil. Admin puede ver pero no modificar.
2️⃣ Validación Email
Si cliente cambia email, debe verificar nuevo email antes de aplicar cambio. Email anterior válido en transiciones.
3️⃣ Auditoría
fecha_modifica se actualiza cada vez que perfil se edita. Log de cambios registra qué campos fueron alterados.
✅ IMPLEMENTADO 🟠 MEDIA
RF-012 Gestión de Estado Cliente Admin puede activar, desactivar o dar de baja clientes. Campo 'estatus' controla acceso al sitio. Cliente inactivo (estatus=0) no puede comprar. Baja registra fecha_baja para auditoría.
1️⃣ Estados Definidos
estatus = 1 (activo/puede comprar), estatus = 0 (inactivo/no puede comprar), fecha_baja != NULL (dado de baja permanente).
2️⃣ Historial Compras
Al dar de baja cliente, compras históricas se mantienen en BD (soft delete). No se eliminan datos para auditoría.
3️⃣ Reactivación
Cliente inactivo puede reactivarse (estatus = 1). fecha_baja se mantiene para auditoría histórica.
✅ IMPLEMENTADO 🟠 MEDIA

🔑 TABLA: USUARIOS

Credenciales y autenticación de clientes

Descripción General de Tabla

Propósito: Almacenar credenciales de login para clientes, separadas de datos personales. Relación 1:1 con tabla clientes. Permite cambio de contraseña y recuperación segura.
Campos Clave: id, nombre_usuario, password (hash), activacion, token, token_password, password_request, id_cliente
Relaciones: FK id_cliente → clientes (1:1)
ID RF Requerimiento Descripción Profesional Reglas de Negocio (3) Estado Prioridad
RF-020 Login de Cliente Cliente debe poder autenticarse usando nombre_usuario (único) y contraseña. Sistema valida credenciales con hash bcrypt. Sesión se inicia después de validación exitosa. Intentos fallidos se registran.
1️⃣ Credenciales Válidas
nombre_usuario debe existir en BD e ignorar mayúsculas/minúsculas. Password se compara con hash almacenado.
2️⃣ Email Confirmado
Cliente solo puede loguearse si activacion = 1 (email confirmado). activacion = 0 bloqueado hasta confirmación.
3️⃣ Límite Intentos
Máximo 3 intentos fallidos. Después se bloquea 15 minutos. Log de intentos se mantiene en sesión/BD.
✅ IMPLEMENTADO 🔴 ALTA
RF-021 Cambiar Contraseña Cliente Cliente logueado puede cambiar contraseña proporcionando contraseña actual (verificación) y nueva contraseña. Cambio genera nuevo hash bcrypt. Sesión se mantiene activa post-cambio.
1️⃣ Verificación Actual
Debe ingresar contraseña actual correcta antes de cambiada. Protege contra cambios no autorizados.
2️⃣ Nueva Contraseña Fuerte
Nueva contraseña mínimo 8 caracteres. Debe contener mayúscula, minúscula, número. No puede ser igual a anterior.
3️⃣ Auditoría
Cambio de contraseña se registra con timestamp. Login se mantiene activo. Email de notificación de cambio.
✅ IMPLEMENTADO 🟠 MEDIA
RF-022 Recuperación Password Cliente Cliente puede solicitar reset de contraseña. Sistema genera token único válido 24 horas. Email con link de reset se envía. Nueva contraseña se establece tras completar verificación.
1️⃣ Token Seguro
Token generado con SHA256/MD5 único. Válido solo 24 horas. Se anula después de usar o expirar.
2️⃣ Email Verificado
Link de reset se envía solo a email en BD. Requiere click de confirmación para proceder a reset.
3️⃣ Nueva Contraseña
Debe cumplir políticas de seguridad (8+ caracteres, mayús, minús, número). No igual a anterior.
✅ IMPLEMENTADO 🔴 ALTA
